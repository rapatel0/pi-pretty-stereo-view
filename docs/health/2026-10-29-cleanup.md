## Findings and actions

1. **Characterization defect (fixed).** `test/config-check.mjs` used
   `console.assert`, which logs but exits 0 — a config regression could never
   fail `npm test`. Replaced with a counted `check()` + `process.exit(1)`.
   Proof: a mutated expectation (`=== 999`) exits 1; the real file exits 0.
2. **Dead-weight ratchet (added).** `test/reachability-probe.mjs` asserts every
   module under `extensions/` is reachable from the entry via static or
   dynamic imports (currently 79/79; `powerline/quote-reply.ts` is reached via
   `import("./quote-reply.ts")`). Wired into `npm test`.
3. **Undeclared dependency (fixed).** Tests imported `jiti` while it was only
   transitively present; declared `jiti@^2.7.0` as a devDependency
   (`knip --include unlisted` now clean).
4. **knip entry blindness (fixed).** `knip.json` declares the real entries
   (`extensions/index.ts`, `test/*.mjs`) so per-file lint gates resolve test
   imports as part of the project graph.
5. **Test-harness duplication (reduced).** One `test/harness.mjs` now owns the
   isolated-agent-dir + jiti setup that all four probes repeated.
6. **Startup measurement.** Bundle has no recurring startup fat: per-module
   top-level execution is <3 ms everywhere; the only large cost is a one-time
   cold transpile of the tree (~5.9 s, then cached by pi's bundle loader).
   Installed pi-bolt 1.0.7 warm start: 5.1 s total with all user extensions vs
   3.7 s with none — the bundle adds ~1.4 s, dominated by bundling, not by
   module work. No runtime code changed in this pass, so startup is unchanged.
